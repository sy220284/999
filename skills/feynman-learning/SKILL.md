# 费曼学习法

## 进入与上下文

明确用户已经主动要求或接受邀请后开始。仅因相关性加载本技能、用户尚未同意时，最多发一次针对当前概念的邀请，然后等待，不开始提问链。
复用当前概念、已有讲解和用户基础；没有具体概念时只问“想检查哪个概念？”用户已经给出解释时直接判断，不要求重复开场。Widget 文案里仍有占位符时先补齐概念。
普通问答已先给讲解后再进入是允许的；不将此时复述称为未看答案的独立理解证据。

## 对话流程

1. **用户先讲**：请用户用自己的话解释这个概念、原理或举例。未作答前不给标准解释，也不在同一条消息中模拟用户回答。
2. **判断实际解释**：依据本轮目标判断正确性、关键要素和理由；表述不同但意思正确应认可。正确且足够说明本轮目标时，直接总结；没有缺口不得硬追问。信息太少时说明尚不能判断，补问一个关键点，不判为错误。
3. **逐个补缺口**：引用用户具体表述，先认可正确部分；每次只处理一个重要遗漏或误解，以追问、提示或最少量讲解帮助用户重新说明。发问后等待，不连续代答。
4. **复核与结束**：依据用户新版解释判断缺口是否补齐；仍有问题则继续帮助。基本正确后，用 2–3 句总结“已讲清什么／修正什么／还需注意什么”，结束本轮。用户想深入时再选一个去术语、类比边界或新情境检查，不强制每轮全做。

用户完全不会或反复卡住时，征询是否先听一个短讲解；用户要求直接解释则直接解释，不以“必须用户先讲”阻止帮助。未完成解释时不宣称掌握。

## 学习反馈与任务衔接

本技能用于帮助用户理解概念。依据本轮讲解调整反馈，但不直接更新正式测验成绩、掌握度、薄弱标记或项目完成状态。
默认在对话中总结已讲清、已修正与仍待理解的内容，不要求用户为“更新学情”额外做题。用户想检验掌握情况时，可邀请一个新情境解释；如明确要正式测验，且已安装 quiz-mastery（测验大师），再交给它创建并提交正常测验。没有测验能力时仅做对话检查，不承诺记录入库。
来自尚未完成的任务时保留来源题号和待做题，按用户意愿接回；已经评分的答案不覆盖或重复提交。若讲解将泄露尚未提交的正式测验题目关键解法，先说明该轮转为不计分辅导，暂停该轮提交；不得把受助后的答案计为独立成绩。

## 简短示例

用户：用费曼法检查我对递归的理解。递归就是函数一直调用自己。
Agent：你说对了“调用自己”。但如果一直调用不停，会发生什么？递归还需要什么条件？
用户：会停不下来，需要终止条件，而且每次要更接近终止条件。
Agent：对，这次补上了终止条件和逐步接近它的过程。你已经讲清这轮的核心；写代码时还要检查每次调用是否确实缩小问题。

## 运行边界

在当前对话中完成任务，优先使用已有内容；需要材料但无法读取附件时，请用户粘贴相关片段，不虚构已读取。无需创建课堂或生成课件。
用户要求停止、换任务或直接说明时尊重其选择，不强制完成全部环节。只依据真实回答反馈，不代写用户回答，不把一次表现等同于长期掌握。不声称已保存记录、修改成绩或创建提醒。

# 最终审校清单

逐项检查。任何“否”都应返回对应步骤修正。

## 一、任务与事实

- [ ] 已明确法域、用户立场、目标产物和使用场景。
- [ ] 已提取会影响实体法、程序法、期间或计算的关键日期。
- [ ] 已区分已核实事实、用户主张、推断和待确认事实。
- [ ] 未擅自补充当事人、金额、日期、送达、证据或程序状态。
- [ ] 显性指令清单已逐项销项：每份要求的文书、每个要求处理的争点、每项附带分析任务、每条负向指令均已覆盖。

## 二、争点与请求权

- [ ] 已按法律关系拆分争点。
- [ ] 已先定性后定量。
- [ ] 每项请求均有请求权基础、构成要件和责任主体。
- [ ] 已区分实体责任、程序救济、费用负担与另行损害赔偿。
- [ ] 已识别主要抗辩、举证责任、期间和管辖问题。

## 三、法条与版本

- [ ] 每条主线法条均通过元典检索，不依赖模型记忆。
- [ ] 引用法条均已用 `article_detail` 读取原文。
- [ ] 已核对法规全称、条号、发布机关、效力层级和地域。
- [ ] 条、款、项序号与原文逐一对应；所处章节或专节未限制其在本案的适用；数额档位、主体类型、程序阶段与本案匹配。
- [ ] 已核对发布日、施行日、效力状态和案件法律事实日期。
- [ ] 元典未收录的规范性文件已联网核验一手来源；已失效、废止或有效期届满的已标注时效状态。
- [ ] “最新／截至目前／尚无”类断言均经带时间限定的检索确认，非凭记忆。
- [ ] 题面未给定的外部数值（利率、统计标准等）未编造：或经检索核实，或以规则文字／占位符表达。
- [ ] 历史事实已使用 `refer_date` 或同等方式查询当时版本。
- [ ] 已检查特别法、司法解释、时间效力和衔接条款。
- [ ] 法条引文逐字一致；归纳内容未伪装成原文引语。
- [ ] 文书本体内每一处引号内容均与检索原文逐字一致；压缩、改写、归纳的内容已去引号改为转述句式。
- [ ] 对话回复中元典返回 URL 的法条均在引用处附可跳转链接。

## 四、案例

- [ ] 争议性、开放性或实务性问题已检索权威案例。
- [ ] 已优先选择指导性、参考、公报或典型案例。
- [ ] 引用裁判理由、判项或原文前已用 `detail` 核对全文。
- [ ] 引文出处层级如实标注：判决书本文、裁判要旨、案情摘要不得互相冒充；仅有摘要或要旨时不写成法院原话。
- [ ] 每个案例已说明关键事实、裁判规则、本案相同点和差异点。
- [ ] 案件名称、案号、法院、裁判日期及链接齐全；缺失项已明确标注。
- [ ] 普通案例未被写成具有普遍约束力的规则。
- [ ] 案例地位标签（指导性／公报／参考／典型）与检索工具返回的类型字段一致；发布主体未升格；权威库查无记录的已按普通判例引用并注明无强制约束力。
- [ ] 援引的案例观点均为该案生效裁判立场；未把被上级法院纠正、撤销或否定的原审认定当作支持性依据。
- [ ] 文书中每一个具体案号的真实性、地位、立场三项均经检索核验；检索不可用或未命中时未凭记忆写出案号。
- [ ] 同一案件不同审级未重复计数；严格命中和类比案例已区分。

## 五、规则适用

- [ ] 每条核心规则已拆分主体、前提、要件、例外、举证责任和后果。
- [ ] “可以”“过错”“造成损失”“不应超过”等条件未被改写成绝对责任或固定比例。
- [ ] 事实与法律要件逐项对应，并注明证据及证明力。
- [ ] 证据不足时使用条件式结论，没有虚构确定答案。
- [ ] 权威规则与自行推理冲突时已修正并解释差异。

## 六、计算

- [ ] 已确认计算项目的法律性质。
- [ ] 已分别列出基数纳入项和排除项及依据。
- [ ] 已核对比率、起算日、截止日和首尾日口径。
- [ ] 已处理部分履行、利率变化、新法施行等分段事件。
- [ ] 已展示公式和关键中间结果，可由用户复算。
- [ ] 分项金额与合计数已脱离原推导重新加总核对，二者一致。
- [ ] 期间类参数（利息期间、期限、年限）已按起止日期单独重算，与正文文字表述一致。
- [ ] 争议性基数或扣减项已检索针对性案例。
- [ ] 数据不足时给公式或区间，没有伪造精确金额。

## 七、文书可执行性

- [ ] 当事人身份、名称、管辖和程序阶段准确。
- [ ] 每项请求明确、可证明、可计算、可执行。
- [ ] 请求部分为判项式表述，未写成论证句或程序性表述。
- [ ] 利息请求写明基数、利率、起止时间和截止事件。
- [ ] 通知写明到达方式、证据和办理期限。
- [ ] 授权文书已区分一般授权与特别授权。
- [ ] 证据目录中的每项证据均对应待证事实。
- [ ] 未核实内容已使用占位符或条件式表达。
- [ ] 体例要素齐全且顺序通行：标题、当事人栏、请求／主文、事实与理由、证据说明、致送对象、落款、附项；程序性论述未置于落款之后。
- [ ] 已完整读取法律文书体例与版式决策指南，并按模板查询表定位该文书类型的模板参考文件；必备要素、填写要点和常见错误逐项复查。
- [ ] 已按文种选择诉讼文书体、说理体、函件体、决议体、章条体或报告体，没有给短篇程序文书、律师函、决议或制度机械增加封面、封底或报告式数据表。
- [ ] 传统诉状、答辩状、上诉状等文书的每个当事主体均以紧凑自然段表达，已知字段用逗号连接；未把字段逐行拆开或生成大块空白当事人表。明确采用官方要素式模板的除外。
- [ ] 诉讼理由、上诉理由、代理／辩护意见和法律分析的小标题能够直接表达本节结论，未使用“法律分析”“其他问题”等空泛标题。
- [ ] 证据清单已使用原生表格；其余每张可见表格均通过“稳定列字段＋多条记录＋确需比较／核对／复算”三项必要性检查。
- [ ] 当事人信息、请求事项、连续法律论证、律师函正文、决议正文和制度章条未被机械表格化；简单数字、少量事件和单一公式未为表格而表格。
- [ ] 字体层级已传递给 docx 生成流程：大标题宋体二号加粗；小标题仿宋四号加粗；正文仿宋四号、默认不加粗，全部黑色。
- [ ] 大标题、小标题、当事人栏、请求、正文、列表、题注、致送对象和落款均采用 1.5 倍行距，表格单元格采用单倍行距（唯一常设例外，权威规则见 docx SKILL 硬规则 13）；没有使用固定行高或连续空行模拟，表格无裁切或异常跨页。
- [ ] 落款日期符合规则：有给定日期则采用；无给定日期则留白，未填成稿当日。
- [ ] 正文时间锚点（“至今”等）基准日来自题目时间线而非生成日期；文书内所有时间表述相互一致。
- [ ] 题目要求的附带分析／说明已落入交付文件（附页或独立附随说明文件），未仅存在于对话回复。
- [ ] 多条文制度文书的内部交叉引用（“本办法第X条”）指向已逐一回查。
- [ ] 立场文书未出现第一人称自认不利的句式；不利内容以审查框架或备位框架呈现。
- [ ] 文书本体不含免责声明、AI 身份说明、核验状态标注、检索过程或工具名（可交付 docx 已通过本体纯净检查脚本）。
- [ ] 每一个最终交付的 docx（含非默认流程生成的）均已运行 `check_docx.py` 且 ERROR 为零。
- [ ] 从头起草的最终 docx 已完成 `render`，页面 PNG 齐全，并已使用 `glm-5v-turbo` 运行 `visual-check`、保存多模态报告；阻断性发现已修复或核实为渲染器差异。

## 八、输出

- [ ] 首句直接回答核心问题。
- [ ] 用户指定的字数、案例数量、格式和交付形态均已机械核对且未超限。
- [ ] 无特殊说明时文书类交付物已生成 docx 并验证可打开。
- [ ] 已区分已核实事实、来源结论、分析判断和待确认事项。
- [ ] 只保留与争点最相关的依据，未堆砌案例和法条。
- [ ] 对话回复中所有检索返回 URL 的来源均已附 Markdown 链接。
- [ ] 免责声明已附在对话回复或交付说明中，且未写入文书本体。

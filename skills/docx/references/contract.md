# Word生成：方法与输入输出

使用scripts/docx_http.py，不直接拼HTTP请求。连接由随包执行器配置管理，普通任务不覆盖连接参数，不索取供应商Key。先探测Python/.NET运行条件，执行C#生成必须在平台隔离环境。

| 方法 | 作用及业务输入 | 结果与检查 |
|---|---|---|
| env/setup | 探测运行条件 | 服务与宿主条件不足时停止，不把探测成功当Word完成 |
| init | 初始化独立任务目录和源码基线 | Program.cs、工程参考；编辑任务副本，不污染共享模板 |
| build | 编译任务Program.cs，并在宿主执行、修复和校验 | 返回报告及真实DOCX；任何失败不交付半成品 |
| extract-text | 读取文件正文 | 文本用于核对事实和结构，不等于法律复核 |
| convert-to-docx / convert-to-pdf | 提供真实源文件及输出路径 | DOCX/PDF，检查格式与内容 |
| render | 提供真实文件及dpi | 页面图用于逐页视觉检查，不以结构检查替代 |

准确CLI参数见SKILL.md和脚本--help。每次任务使用独立work-dir；源码编译后的发布包/宿主DLL执行、初始化空请求、渲染参数等由脚本执行，运行环境不支持或返回不符合预期则停止，不能临时换链路后宣称原检查通过。

JSON报告与Word/PDF/ZIP文件由脚本分别解析；HTTP200不等于业务成功。命令失败头、报告失败、缺报告或非法ZIP路径均停止。输出文件检查签名与核心结构，文件名采用明确输出路径，不盲信服务返回名称。超时/权限/额度/大小错误说明未完成，不伪造下载链接。

产出后执行正文检查、渲染与逐页视觉复核，并核对用户事实、金额和法律引用。身份等普通信息可待补，但关键事实不得编造。实际链路仍需在目标环境验证；离线测试不代表已生成或已完成效果验收。

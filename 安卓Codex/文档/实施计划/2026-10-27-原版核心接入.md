# 原版核心接入代码计划

按用户指令由当前会话直接实施；此阶段不运行构建、打包或模拟器。

目标：在手机本机启动固定源码版本的 codex-app-server，通过双向逐行 JSON-RPC 接入中文原生界面。保留已有 Kotlin 工作区和会话数据；原版会话使用独立目录，防止混用上下文。

1. core/AppServerConnection.kt：请求编号、并发响应分发、通知、服务端请求、错误、超时、关闭及帧长限制。测试源码覆盖乱序、字符串请求 ID、断管、未知审批、取消。
2. core/OriginalCodexClient.kt：按上传版本 TS 类型构造 initialize/initialized、会话、回合、账号、模型、配置、MCP、技能、插件与 Hooks 调用。未知服务端请求返回 -32601，审批绝不自动允许。
3. app/OriginalCoreHost.kt：只执行安装目录内原生文件；独立 stdin/stdout/stderr；启动错误明确；只保留脱敏错误，不把凭证或完整协议写日志。连接和运行任务属于 Application 生命周期。
4. app/OriginalCoreScreen.kt：中文独立入口；原版会话列表、创建/恢复、流式文本、审批、补充输入、停止及账号状态。原版进程未随包提供时明确报告缺失，不退回另一内核伪装成功。
5. 运行核心：保留精确版本、Android 适配补丁与可复现构建脚本。只提交源码，不执行脚本。

重点复查：服务端请求必须异步处理，不能阻塞响应读取；退出立即使所有等待请求失败；取消只中断对应回合；恢复会话不再次重放历史用户指令；凭证不落入项目文件或日志；UI离开不重复启动任务；未执行测试必须明确标注。

验收边界：代码静态审阅与 git diff --check；新增 JVM/Android 测试仅编写，不执行。本轮不宣称二进制已嵌入、原版核心已运行或完整功能复刻验收通过。

## 继续：Android 原版凭证后端

在上游 DefaultKeyringStore 的 Android cfg 分支接入宿主本机 Unix socket。协议采用有界长度二进制帧，无新序列化依赖。双向使用 SO_PEERCRED 验证对端 PID/UID；宿主只接受当前原版进程。凭证按 service/account 绑定 AAD，经 Android Keystore AES-GCM 加密后原子写入 noBackupFilesDir。账号和 MCP 均强制 keyring，桥接失败不回退明文。新增持久化、删除、拒绝错误 PID 的 Android 测试源码，仅静态审阅。

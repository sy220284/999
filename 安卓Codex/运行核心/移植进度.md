## 本轮代码调用链

- `NativeCoreProcess` / JNI：从 nativeLibraryDir 启动 PIE 可执行文件，UTF-8 参数、独立 stdin/stdout/stderr、exec 成功确认、进程组及子工具树清理。核心设置 subreaper，尽量收留脱离中间父进程的工具；/proc 无法读取、系统拒绝 subreaper 或超过扫描上限时，子树清理的覆盖需后续设备核验。
- `AppServerConnection`：逐行双向 JSON-RPC、并发请求和乱序响应、通知与审批请求分流、原样保留字符串/数字 ID、超时、断管清理、16MB 帧限制。写入超时关闭连接；不自动重发有副作用的请求。
- `OriginalCodexClient`：初始化及确认；会话创建/恢复/读取/分页/分叉/归档/命名/压缩；回合发送/追加/中断；API 密钥、设备码和浏览器登录/取消/退出；模型、账号、配额、技能、MCP、Hooks 和已安装插件查询。字段以上传版本生成的 TS 类型为依据。
- `OriginalCoreHost`：Application 持有连接，前台服务持有任务；与 Kotlin 对话任务互斥；回合完成、断流、取消、连接清理；原版会话单独持久化，项目为“原版项目”。
- `OriginalCoreScreen`：中文侧栏入口、原版会话与任务视图、命令/文件审批、模型选择、用户问题和 MCP 平面表单及 URL 交互；未知请求返回明确错误。尚未提供细粒度权限界面，权限请求返回空授权。
- `AndroidTrustBundle`：导出应用信任的 CA，供 Rust HTTP/WebSocket 使用；不关闭证书校验。

## 凭证与权限边界

账号与 MCP 均强制使用 keyring。补充的 `android_keyring.rs` 在 Android 目标替换上游 DefaultKeyringStore，通过本机 Unix socket 与宿主通信；双方校验 PID/UID，宿主仅接受当前核心进程，工具子进程不能直接通过桥接取凭证。`OriginalCredentialVault` 使用 Android Keystore AES-GCM 和绑定 service/account 的 AAD，将密文原子保存在 noBackupFilesDir。桥接失败直接返回错误，不允许回落明文文件。此跨语言持久恢复链路已写入代码，尚未编译、执行或验证 Android socket/Keystore 行为。

连接设置中的工具服务现在通过原版 MCP 管理页显式导入、核对并确认保存；原版启动时不再注入 URL 覆盖。管理页及原版入口提供 MCP OAuth 发起、打开授权页和完成通知；关闭提示不会伪称取消服务端 OAuth。已有账号优先恢复，设置中的 API 密钥可主动切换使用。

Android UID 隔离不能限制命令只访问项目目录。启动前显示此限制并要求本次启动同意；原版 thread/start 使用 danger-full-access 与 untrusted 审批。此组合没有桌面 Landlock/bubblewrap 的项目沙箱保证。进程内存和本应用其他文件仍可能被同 UID 的命令访问。
